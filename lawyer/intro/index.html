Lawyer

现在用的网页版：/lawyer/webinterface/（本页只是项目介绍，已移到 /lawyer/intro/）

个人律师 · 把关者 —— 在用户和 AI 之间，先把要求按规则梳理成一段 AI 能完美理解、不出错的文本，再发给 AI 执行

一、这是什么

Lawyer 只是一个有限的逻辑流程图生成器。它不需要理解万事万物，只需要理解这几个 project，而且这几个 project 保持千古不变，除非人为改动。

因为没办法让 AI 主动按规则做事，所以只能自己先把要求按规则梳理出来。表面上多了一层输入、复制、粘贴、发送，实际上是增加了效率：一次把文本生成对，AI 一次跑对，省了后面的来回纠错。

生成的一段文本里要提示前因后果、提示接口、提示标准。

二、怎么工作

步骤做什么
1. 触发按快捷键或按键触发一个 project，不一定是语音交互，照理说按键是最快的
2. 一级菜单选 project
3. 二级菜单点选选项，不用打字
4. 生成文本按该 project 的规则生成一段文字
5. 确认、发送用户说确认，就发送到 AI：豆包手机、Muse、复制粘贴都可以

例子（菜谱）：按 Control+Option+Command+C+P，下来菜单选猪肉、牛肉、鸡肉，再选几个常用的蔬菜，生成一段文字，回车发送，这样才是最快的。

三、壳和内核

App 只是一个壳，壳就是一级菜单、二级菜单。菜单里面有什么项目、每个 project 的规则综述，都放在网上，可以后台改。

壳做成什么都可以：APK、网页、Linux 顶部栏上面的按钮。改只改后台的数据，所有前台的壳都会跟着改。

平台壳的形式触发和操作
iOS快捷指令iPhone 16 单独的按键触发；打开就是列表，选菜谱，点猪肉、点土豆，生成文本后自动保存在剪贴板，打开任何一个 AI App（例如 Muse）粘贴发送即可
macOS快捷指令键盘快捷键或菜单栏触发，和 iOS 快捷指令同一个，iCloud 同步
AndroidAPK直接做个 APK 即可，打开点选
Linux顶部栏 App，像音乐播放器一样点选即可；Linux 目前只有 Muse 的网页版，用处不大

五、菜谱的规则（目前唯一已填的 project）

按 Map 里 DIY 菜谱页的规则：聊天里给的是按手头食材改过的 DIY 版，机器推的是云菜谱原版原样，机器菜谱本身没法 DIY。

  • 以主材为主：主材才是关键，其他只是手头可换的料，不是必须全含的筛选条件。
  • 蔬菜可以替换原菜谱中的蔬菜，所以原菜谱中不一定本来就是所选蔬菜。
  • 食材能替换，按手头有的来；加一种新食材只把时间加一点、调料加一点，绝不全部翻倍；同一种食材加量才按比例翻倍。
  • 调料一碗，所有调料提前放进一个碗，整碗倒进去；可数食材按个数，不给克数；称重的调料用克。
  • 备 2 份，炒一份，冰箱留一份。
  • 推菜时间是定死的，需要加长时告诉用户改哪一步、从几分钟改到几分钟，由用户在机器上手动改。土豆必须炖透，炒不行。

生成文本的格式：形成一段文字的菜谱总结，食材是一个部分，酱料是一个部分，方便一次性准备好。菜谱通过小 C 机器的方法推送，按原菜谱推送即可，推上去后机器屏幕显示菜谱，用户按开始就行。

二级菜单目前：主材——猪肉、牛肉、鸡肉；常用蔬菜——土豆、白菜、芹菜。
